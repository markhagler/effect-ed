Lesson 6

Many Things at Once: Fibers

One cook can keep many recipes going by using bookmarks, and can cleanly stop any of them. Effect calls a bookmark in a running recipe a fiber. Fibers let you run recipes side by side, race them, and interrupt them, which Promises can't do.

The story

Remember: still one cook, Sam. Sam is making three smoothies for three customers. Sam does not grow extra arms.

Bookmarks. Sam puts a bookmark in recipe 1 while it blends, starts recipe 2, bookmarks that, starts recipe 3. Three recipes in progress, one cook.
Each bookmark is a fiber. It remembers where in the recipe we were, so Sam can pick it back up when the bell rings.
Customer 2 leaves. With a receipt, too bad, the smoothie gets made anyway. With a fiber, Sam pulls the bookmark out. Effect calls this interruption.

The picture

The tiniest code

Run several cards at once. Effect.all takes a list of cards and gives back one card that produces a list of results. The concurrency option is "how many bookmarks may Sam have open at once."

import { Effect } from "effect"

const makeSmoothie = (name: string) =>
  Effect.sleep("3 seconds").pipe(Effect.as(`${name} 🥤`))

const three = Effect.all(
  [makeSmoothie("mango"), makeSmoothie("berry"), makeSmoothie("kiwi")],
  { concurrency: "unbounded" }      // as many bookmarks as needed
)
// three : Effect<string[]>

Effect.runPromise(three).then(console.log)   // ~3 seconds, not 9

Race. Two cards start; the first to finish wins, and the loser is interrupted (its bookmark is pulled).

const fastest = Effect.race(makeSmoothie("mango"), makeSmoothie("berry"))

A bookmark you can hold. Effect.forkChild starts a card in the background and hands you the fiber. Fiber.join waits for it. Fiber.interrupt stops it.

import { Effect, Fiber, Console } from "effect"

const program = Effect.gen(function* () {
  const fiber = yield* Effect.forkChild(makeSmoothie("mango"))   // start it, keep the bookmark
  yield* Console.log("customer is waiting...")
  yield* Effect.sleep("1 second")
  yield* Console.log("customer left!")
  yield* Fiber.interrupt(fiber)                                  // pull the bookmark
  yield* Console.log("stopped the mango smoothie")
})

Effect.runPromise(program)

Try that with a Promise. There is no way to stop orderSmoothie("mango") once it's called.

Check yourself

  
1. Did Sam ever do two things at the exact same instant? Then how did three smoothies take three seconds?No. Sam only did the short steps. The blenders did the long waiting parts, all overlapping, while Sam held three bookmarks.

  
2. What is a fiber, in kitchen words?A bookmark in a half-finished recipe: it remembers where Sam was, so Sam can come back to it, or pull it out.

  
3. A customer leaves. What happens to their smoothie with a Promise? With a fiber?Promise: it gets made anyway; nothing can stop it. Fiber: Sam interrupts it, the recipe stops at its next step, and any cleanup it promised still runs.

  
4. In Effect.all with concurrency: 2, how long do three 3-second smoothies take?About 6 seconds. Two run together (3 s), then the third runs alone (3 s). Try it in the demo above.


  

    Teacher notes
    
    
      
  • The word for "many things in progress at once" is concurrency. It's not "many things happening at the same instant," which is parallelism and needs more cooks. Say "in progress," never "at the same time," and you'll avoid a year of confusion.
    • 
      
  • Effect.forkChild makes the fiber a child of the current one. If the parent finishes or is interrupted, the child is interrupted too. Effect 4 also has forkScoped and forkDetach for other lifetimes; skip them.
    • 
      
  • Leaving out concurrency means one at a time.
    • 
      
  • Interruption is polite. A fiber isn't killed mid-instruction; it stops at the next step boundary and runs its cleanup. Compare pulling the plug to pressing the off button.
